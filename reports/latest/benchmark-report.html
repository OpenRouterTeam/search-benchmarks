Methodology notes

How to read this report
Scoring
Headline numbers use failed-as-zero: tasks that exhausted retries count as 0. The failed-excluded column averages only graded tasks; a large gap between the two signals harness reliability problems, not search quality. Each score carries a 95% Wilson interval; the green Best badge requires the leader's interval to clear every runner-up's, otherwise the row is marked Leading (within noise).
Grading
Grader: openai/gpt-4.1 via openrouter, matching upstream's gpt-4.1 grading for comparability. Override with SEARCH_EVALS_GRADER_MODEL.
Cost
Provider-reported request cost where available, split by agent vs grader stage. "Known" totals exclude attempts whose providers did not report cost.
Surfaces
Each engine is run across the search-turn ladder: plugin · 1-turn · 5-turn · 25-turn. Plugin is one pre-inference search on the verbatim user message; server-tool rows use model-authored searches. Plugin vs 1-turn isolates query quality, while 1-turn→5-turn→25-turn isolates search depth. Per-result content uses each engine's configured default unless a row says otherwise.
Harness scope — search, no fetch
Not comparable to full multi-tool agent benchmarks: those agents add model-driven page fetching + code tools. Here the model searches and reads capped excerpts but does not fetch full URLs — web_fetch is off, measured neutral-when-capped and unobservable via the API (it executes but reports no usage). Scores therefore sit below fetch-enabled agents by design; read engine and surface deltas, not absolute levels. firecrawl is omitted (BYOK key not configured → broken retrieval), and native is omitted (plugin-native 400s for non-OpenAI models, and server-tool native ignores the call/char caps — not a like-for-like backend).
Comparability
Rows in one suite leaderboard share the same dataset fingerprint and suite instructions (enforced by the config hash). Smoke/probe runs are excluded. All shown rows are pinned single-engine server-tool or plugin lanes at a fixed reasoning model, so deltas isolate the search backend and the surface. Plugin-route rows inherit OpenRouter's default search_prompt (the instruction attaching results to the message), an uncontrolled variable of that surface — read plugin as a product, not a like-for-like backend vs the server-tool rows.
